# PaqetFire v0.6.36

This release provides comprehensive enhancements and resilience fixes for the native **Upstream OpenVPN (Multi-hop)** routing subsystem, completely eliminating kernel-level network lockouts and black holes.

## Upstream OpenVPN & Multi-Hop Routing

- **Native OpenVPN 2.7.8 & DCO Driver**: Bundles OpenVPN 2.7.8 x64 and the OpenVPN Data Channel Offload (`ovpn-dco`) kernel driver. Driver installation is provisioned automatically with TAP-Windows fallback.
- **Selective Domestic Bypass**: All non-Iran / filtered traffic is routed through the upstream OpenVPN tunnel via Paqet (`socks-proxy 127.0.0.1 1080`), while domestic traffic (`geosite:category-ir`, `geoip:ir`) continues to route directly with zero overhead.
- **Overview Card & Latency Probes**: The Overview card dynamically displays the OpenVPN exit IP address and country flag when active. Latency probes automatically measure response times through the active upstream tunnel.
- **DPAPI Credential Security**: OpenVPN passwords are encrypted with Windows DPAPI and retained securely across sessions and profile edits.

## Kernel & Network Stack Reliability

- **WFP Lock Elimination**: Automatically strips `block-outside-dns` from imported `.ovpn` configurations and applies `pull-filter ignore "block-outside-dns"`, preventing third-party Windows Filtering Platform locks on physical adapters.
- **Graceful Termination via Win32 Service Event**: Uses OpenVPN's native Windows `--service` event signaling for clean adapter release and routing teardown.
- **Defense-in-Depth Route Purge**: Actively cleans up lingering `0.0.0.0/1` and `128.0.0.0/1` redirect-gateway routes on unexpected termination, crashes, or broker startup, ensuring network traffic can never be black-holed even during abnormal process termination.
- **Pre-flight VPN Conflict Detection**: Automatically scans for external standalone OpenVPN processes (`openvpn.exe`, `openvpn-gui.exe`) before connecting, alerting the user to avoid firewall and driver collisions.
- **8.3 Short Path Canonicalization**: Enhanced orphaned engine cleanup to handle short and long DOS path differences transparently.
